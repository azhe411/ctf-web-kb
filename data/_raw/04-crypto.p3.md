## [g-hash] 哈希与消息认证——碰撞与长度扩展是 CTF 考点

### [hash-table] MD5/SHA 输出长度速查 | easy | MD5;SHA1;SHA256;输出长度 | 哈希长度表
> 见到 32/40/64 位十六进制串先对表，避免把哈希当加密去「解密」。

#### 这个条目的作用

哈希是**单向函数**：只能由明文算出哈希，不能由哈希反推明文。CTF 里给一串 32/40/64 位十六进制，十有八九是哈希。本条目的作用就一件事：**数长度、对表、说出算法名**，然后决定下一步是撞库、看弱点还是放弃这条路。最大的坑是把哈希当加密去「解密」——哈希根本不可逆，方向错了浪费一小时。

#### 前置条件

- 本机有 Python 3（生成/核对哈希用），或能打开 CyberChef。
- 网络可用（撞库需要访问 cmd5.com / somd5.com 等）。
- 了解十六进制：每个 hex 字符表示 4 位（bit），所以「输出 N bit」对应「N/2 个 hex 字符」。

#### 第 1 步：数长度，对照长度表定算法

把密文粘进编辑器，数一下 hex 字符个数（32 / 40 / 56 / 64 / 96 / 128），对下表：

| 算法 | 输出位长 | 十六进制长度 | 典型特征 |
| --- | --- | --- | --- |
| MD5 | 128 bit | 32 | 最常见，32 位全小写 hex |
| MD4 | 128 bit | 32 | 老算法，罕见 |
| NTLM | 128 bit | 32 | 同 MD5 长度，Windows 口令哈希 |
| SHA-1 | 160 bit | 40 | 40 位 hex |
| SHA-224 | 224 bit | 56 | 少见 |
| SHA-256 | 256 bit | 64 | 64 位 hex |
| SHA-384 | 384 bit | 96 | 少见 |
| SHA-512 | 512 bit | 128 | 128 位 hex |

用 Python 亲手验证一遍「同样输入、不同长度」：

```python
import hashlib
for name in ["md5", "sha1", "sha224", "sha256", "sha384", "sha512"]:
    h = hashlib.new(name)
    h.update(b"flag")
    d = h.hexdigest()
    print(f"{name:8s} 长度={len(d):3d}  {d[:24]}...")
```

**预期结果**：依次打印长度 32、40、56、64、96、128。**如果不行**：hashlib 是 Python 内置模块无需安装；检查是否把 `b"flag"` 写成了 `"flag"`（字符串与字节串编码不同，哈希值会变）。

> [!tip] 见到 32 位 hex 先别默认 MD5，先看题目场景：Windows/域环境、明文是口令 → 先试 NTLM（hashcat `-m 1000`）。

#### 第 2 步：区分「同长度、不同算法」的 32 位哈希

32 位 hex 可能是 MD5 / MD4 / NTLM，三选一：

- **MD5**：通用场景默认选项。
- **NTLM**：NTLM = MD4(UTF-16LE(口令))，出现在 Windows 登录、域用户、SMB 等题目，特征是题目描述带 "NT hash" / "LM" / Windows。
- **MD4**：极罕见，几乎只在纯密码学习题里。

判断方法：把值丢进 hash-identifier（Kali 自带），或对照 hashcat 的示例哈希页看字符形态。最快的路径是：**直接拿 hashcat 试 `-m 0`（MD5）和 `-m 1000`（NTLM）两种模式各跑一遍**，哪个出结果就是哪个。

#### 第 3 步：撞库 / 爆破

在线撞库（最快，零配置）：

- [cmd5.com](https://www.cmd5.com) / [somd5.com](https://www.somd5.com)：粘贴哈希直接查，常见弱口令秒出。
- 明文是常见中文/数字/生日组合时，cmd5 通常直接命中。

本地爆破（hashcat，适合字典命中不了的情况）：

```bash
# -m 0 是 MD5，-m 1000 是 NTLM
hashcat -m 0 hash.txt rockyou.txt -r rules/best64.rule
# 6 位纯数字直接掩码爆破
hashcat -m 0 hash.txt -a 3 ?d?d?d?d?d?d
```

**预期结果**：常见口令（`admin`、`123456`、`flag` 相关词）几秒内出明文。**如果不行**：换大字典（rockyou 完整版）、加规则、上掩码；还是不行就看题目有没有给「盐」或提示（见下一步）。

#### 第 4 步：识别加盐并尝试常见拼接

**现象**：相同明文多次生成哈希结果不同，或明明很简单的口令却撞不出来 → 大概率加盐。

先试最常见的三种拼接，用脚本快速验证：

```python
import hashlib
target = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"   # 待破解的 md5
salt = "题目给的盐值"                          # 没有就试常见值
words = ["admin", "123456", "flag", "ctf"]    # 候选明文
for w in words:
    for cand in [w + salt, salt + w, w.upper() + salt]:
        if hashlib.md5(cand.encode()).hexdigest() == target:
            print("命中:", cand)
```

**预期结果**：若拼接方式猜对，打印出完整明文。**如果不行**：盐是随机数且每人生成一份（服务端当场随机）时撞库无意义，改找哈希生成代码，看盐的来源和拼接顺序（`flag+盐` / `盐+flag` / `盐+flag+盐` 都见过）。

#### 第 5 步：区分「这条题考的不是哈希本身」

给了哈希值 ≠ 题目就是撞库题。三条旁路要记牢，见到对应特征直接跳：

- 值是 32 位且题是 **PHP 代码审计** → 可能是 [hash-0e] 0e 弱比较（`==` 绕过）。
- 校验逻辑是 `hash(secret + 可控数据)` 且算法是 MD5/SHA1/SHA256 → 可能是 [hash-len] 长度扩展攻击。
- 题目要求「找两个不同输入哈希相等」 → 找碰撞。

#### 常见错误与排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 拿 32 位 hash 去「解密」 | 误以为哈希可逆 | 哈希单向，只能撞库/爆破，先对表说算法名 |
| 32 位 hex 按 MD5 破不出 | 其实是 NTLM/MD4 | hashcat 加跑 `-m 1000`；看题目是否有 Windows 场景 |
| 相同明文哈希不同 | 有随机盐 | 找生成代码确认盐来源与拼接顺序 |
| hashcat 报「no hashes loaded」 | 模式号选错或文件格式不对 | `-m 0` MD5 / `-m 1000` NTLM；哈希文件每行一个、无空格 |
| 爆破很久无结果 | 口令强度高或字典太小 | 先试在线撞库，再上规则/掩码，最后考虑加盐 |

> [!warn] 哈希是单向的：永远不要试图「解密」哈希，只能撞库/爆破/找碰撞。看到 32/40/64 位 hex，先报算法名，再决定打法。

#### 实战要点

- 见到 32/40/64 hex 第一步永远是对表报名字，别急着猜。
- 加盐题直接用 hashcat 的 `-m 10`（md5($pass.$salt)）与 `-m 20`（md5($salt.$pass)）各跑一遍，省去手写拼接。
- 撞库前确认哈希是「原样小写 hex」：题目如果给了大写，先转小写再查。
- 哈希值本身常是「中间产物」：解出明文后往往还要再走一层（如明文是 Base64，再解出 flag）。

### [hash-0e] 0e 科学计数碰撞与弱比较 | medium | 0e碰撞;弱比较;PHP | 科学计数法碰撞
> PHP 的 == 会把形如 0e 数字串当科学计数法比较，构造两个值都为 0 的哈希即可绕过。

#### 这个条目的作用

PHP 的松散比较 `==` 有一个著名陷阱：当两个字符串都形如 `0e` 后面全是数字（即 `0e12345...`）时，PHP 先把它们当作**科学计数法数字**——`0e` 开头意味着 `0 × 10^幂`，结果恒等于浮点数 **0**，于是两个完全不同的字符串 `==` 比较结果为真。攻击者只要找到两个「哈希值以 0e 开头」的不同明文，就能绕过 `md5($a) == md5($b)` 这类校验，不碰密码学任何困难问题。这是 PHP 类型混淆（Type Juggling）家族里 CTF 出场率最高的考点。

#### 前置条件

- 确认题目是 **PHP 场景**：源码审计、`.php` 文件、日志显示 PHP，或题目直接给代码片段。
- 确认校验语句用的是 `==`（松散比较）而不是 `===`（严格比较）——后者不受影响。
- 能提交 HTTP 请求（浏览器地址栏或 curl 都行）。

#### 第 1 步：确认比较运算符是 `==`

先读代码。能绕过的形态长这样：

```php
if (md5($_GET['a']) == md5($_GET['b'])) {
    // 通过
}
if (md5($_GET['a']) === md5($_GET['b'])) {
    // === 严格比较：不适用 0e
}
```

**原理**：`==` 比较两个字符串时，若两边都匹配科学计数法数字模式（`0e[0-9]+`），PHP 把它们转成浮点数再比。`0e462097...` 转成浮点就是 `0.0`，两个 0.0 自然相等。`===` 先比类型（都是 string）再比字节内容，`0e462...` 与 `0e830...` 内容不同 → false。

**预期结果**：看到 `==` 就有戏，看到 `===` 直接放弃 0e 路线。**如果不行**：校验里还有 `is_string()`、长度检查等额外约束，先满足它们再谈 0e。

#### 第 2 步：准备两个 0e 开头的哈希

已知的 0e 开头 MD5 串（明文与哈希都验证过，可放心直接用）：

| 明文 | MD5 |
| --- | --- |
| `240610708` | `0e462097431906509019562988736854` |
| `QNKCDZO` | `0e830400451993494058024219903391` |
| `s878926199a` | `0e545993274517709034328855841020` |
| `s155964671a` | `0e342768416822977524120578001377` |

不要背，本机验证一遍（顺便建立信任）：

```python
import hashlib
for s in ["240610708", "QNKCDZO", "s878926199a", "s155964671a"]:
    print(s, hashlib.md5(s.encode()).hexdigest())
```

**预期结果**：四个输出都以 `0e` 开头、后面全是数字。**如果不行**：检查 Python 是否把明文误转码（比如带换行），保持原样字符串。

#### 第 3 步：构造绕过请求

两个参数各取表里一个不同明文即可（校验比较的是两边哈希值相等，不是明文相等）：

```bash
curl "http://target/page.php?a=240610708&b=QNKCDZO"
# 或任选两行不同明文：a=240610708&b=s155964671a 也行
```

**预期结果**：页面出现「通过/flag/登录成功」等绕过后的内容。**如果不行**：把参数名对齐题目代码（`$_GET['a']`/`$_GET['b']` 换成真实参数名）；确认中间没有 `md5($x) === $哈希` 的严格比较兜底。

#### 第 4 步：掌握两个常见变体

变体一：哈希与**整数 0** 比较。代码形如 `md5($input) == 0` 时，普通字符串一样打——任何**不以数字开头**的哈希串在与整数 0 比较时都会被转成 0：

```php
if (md5($_GET['a']) == 0) { /* 传 a=0 → md5("0")="cfcd2084..." 非数字开头 → 转 0 → 通过 */ }
```

变体二：0e 不限于 MD5。凡是「十六进制输出以 0e+数字 开头」的哈希都适用，SHA1 也有现成对子：

```python
import hashlib
for s in ["aaroZmOk", "aaK1STfY"]:
    print(s, hashlib.sha1(s.encode()).hexdigest())  # 都应以 0e 开头
```

> [!danger] 0e 绕过只在 PHP 的 `==` 下生效；`===`、`strcmp` 严格比较、或非 PHP 环境（Python/Node 不存在这种字符串比较陷阱）都不适用。PHP 7.2+ 给 `md5()` 传数组会直接抛 TypeError，别再拿「数组绕过 md5」的旧姿势碰新版。
>
> 若题目是 `md5($a) === md5($b)`，改用「真碰撞」思路：找两个不同明文产生完全相同 MD5（用 fastcoll 等工具生成），难度显著上升，`0e` 那套不适用。

#### 常见错误与排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 用了 0e 串但没过 | 比较是 `===` 或非 PHP 环境 | 回读代码确认 `==`；`===` 改用真碰撞 |
| 提交后哈希串不是 0e 开头 | 明文抄错/被加换行 | 先用上面 Python 脚本核对四个已知串 |
| 过了第一关还有第二关 | 校验是多层（先 == 再 ===） | 逐层分析，别只处理第一处 |
| PHP 版本报错 | 传数组给 md5（7.2+ 抛异常） | 用 0e 字符串方案，不走数组路子 |

#### 实战要点

- 看到 PHP 题先点一遍：校验里有没有 `==`、`!=`、`in_array($x, [0])` 这类松散比较，有就查两边哈希是否碰巧 0e 开头。
- 四个已知串背不住没关系，记住「240610708 / QNKCDZO」两个就够，本机 `python` 随时验证。
- 0e 的本质是「类型混淆」：同源码里常连着 `strcmp`、`in_array`、`switch` 的坑，看到一个就顺藤摸瓜看旁边有没有同类。
- 服务端存的是固定哈希值时，找一个已知 0e 串与它「相等」，同样能绕。

### [hash-len] 长度扩展攻击 | hard | 长度扩展;哈希;SHA1 | Length Extension
> MD5/SHA1/SHA256 都是 Merkle-Damgård 结构，未知密钥前置拼接时可用长度扩展伪造。

#### 这个条目的作用

长度扩展（Length Extension）是 MD5 / SHA-1 / SHA-256 这类 Merkle-Damgård 结构哈希的**结构性弱点**：当服务端用 `hash(secret + message)`（密钥在前、消息在后）做校验时，攻击者虽然不知道 secret 是什么，但只要知道 **secret 的长度**、**原始消息**和**最终哈希值**，就能在消息后面拼接任意内容，并算出对应的新哈希——服务端会认为「secret + 原消息 + 附加内容」是合法数据。典型场景：`sha1($secret . $data) == $_GET['sig']`，把 `data` 从 `role=user` 改写成 `role=user&role=admin` 并伪造签名。

#### 前置条件

- 找到服务器校验代码，确认形态是 `hash(secret . 可控数据)`（**secret 在前**）。
- 算法是 MD5 / SHA-1 / SHA-256 之一（SHA-3、HMAC、`secret` 在后不适用）。
- 知道 secret 长度（未知时从 1 试到 64 也能搞定）。
- 有一份「原始消息 + 对应签名」的合法样本。

#### 第 1 步：判断题目是不是长度扩展题

用三个特征自检：

1. 校验形如 `$sig === sha1($secret . $data)`（或 md5/sha256），且 `$data` 是你可提交的参数。
2. 代码里 `$secret` 是固定的未知字符串，但**长度**可以猜（常见 8/16/32）。
3. 服务端会根据 `$data` 解析出业务字段（如 `admin=0` → 改成 `admin=1`）。

```php
// 典型形态（代码审计题常见）
$data = $_GET['data'];
$sig  = $_GET['sig'];
if (sha1(SECRET . $data) !== $sig) die("bad");
echo do_stuff($data);   // 解析 data 并执行业务
```

**命中即打**。**如果不命中**：`hash($data . $secret)`（密钥在后）或 HMAC 形式，长度扩展不适用，回代码找别的洞。

#### 第 2 步：安装工具（两条路任选）

Linux/WSL 用 hash_extender（C 写的，快）：

```bash
git clone https://github.com/iagox86/hash_extender
cd hash_extender && make
./hash_extender --help   # 看到用法说明即成功
```

Windows 不想编译就用 Python 的 hashpumpy：

```bash
pip install hashpumpy
```

**预期结果**：工具能跑 `--help` 或 `import hashpumpy` 不报错。**如果不行**：Windows 下优先 pip 路线；源码编译失败多半缺 make/gcc，别耗时间在编译上。

#### 第 3 步：计算伪造签名与数据

核心调用就一行。以 hashpumpy 为例：

```python
import hashpumpy
from urllib.parse import quote

sig_old = "已知的原始签名 hex"      # 服务端给过你的合法签名
data_old = b"role=user"            # 与 sig_old 对应的原始数据（就是 $data）
append = b"&role=admin"            # 你想追加的内容

for key_len in range(1, 65):       # 不知道密钥长度就全试
    sig_new, data_new = hashpumpy.hashpump(sig_old, data_old, append, key_len)
    print("key_len=", key_len)
    print("new sig :", sig_new)
    print("new data:", quote(data_new))   # URL 编码后才是能提交的形态
```

**预期结果**：每行打印出 `key_len` 对应的新签名与编码后的新数据。**注意**：`data_new` 里包含哈希算法的**填充字节**（`\x80`、零填充、长度字段），这是长度扩展的必然产物，**必须完整提交**，不能手动删掉——服务器会把整段当作 `$data` 重新哈希，这段填充正是让校验成立的关键。

> [!tip] 看不懂填充没关系，记住结论：MD5/SHA1/SHA256 的块大小都是 64 字节，填充 = 补块 + 长度字段。工具全包了，别手写。

#### 第 4 步：提交验证

把第 3 步输出的 `new sig` 和 URL 编码后的 `new data` 带上：

```bash
curl "http://target/page.php?data=<第3步输出的new_data>&sig=<第3步输出的new_sig>"
```

**预期结果**：校验通过，服务端按追加内容执行业务（如 `role=admin` 生效，返回管理员页面/flag）。**如果不行**：见排查表，绝大多数是密钥长度猜错或没做 URL 编码。

#### 第 5 步：密钥长度未知时的标准化打法

不知道 `$secret` 长度？循环试即可，看哪个长度返回「非校验失败」的响应：

```bash
for L in $(seq 1 40); do
  sig=$(python3 -c "import hashpumpy,sys; print(hashpumpy.hashpump('原签名',b'原数据',b'追加',int('$L'))[0])")
  # 用 sig 发请求，记录每个 L 的 HTTP 状态码 / 页面特征，找到校验通过的那个
done
```

或更省事：先看题目提示（经常直接给了长度），给了就只跑一次。

#### 常见错误与排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 签名总不对 | 密钥长度猜错 | 循环 1..64 全试；或找提示里的长度 |
| 格式/算法选错 | `--format` / hashpump 参数给错 | md5→`--format md5`，sha1→`--format sha1`，sha256→`--format sha256`；签名必须全小写 hex |
| 提交后 data 被改写 | 没 URL 编码（含 `\x80`、`%`、`&`） | 用 `quote(data_new)` 全字节编码后再拼 URL |
| 校验过了但业务没变 | 追加内容格式不对 | 追加内容要贴合服务端解析格式，如 `&role=admin` 前必须有原始参数的结尾 |
| 提示「signature invalid」且重试无效 | 服务端是 HMAC 或 secret 在消息后 | 长度扩展不适用，换攻击面 |

> [!warn] 用 `secret + message`（密钥在前）才适用；`message + secret`（密钥在后）与 HMAC 都不受影响。提交的必须是「secret+原消息+填充+追加」的完整链条——服务器会把 `data` 参数原样接到 secret 后面重新哈希，所以 `data` 里带着填充字节是正常且必须的，别手贱删掉。

#### 实战要点

- 看见 `sha1($secret . $_GET['data'])` 或 `md5($secret . $data)`，条件反射喊「长度扩展」。
- 不知道密钥长度先 1..64 全试一遍，比猜准快。
- hashpumpy 的 `data` 返回的是 `bytes`，提交前 `urllib.parse.quote` 一步到位。
- 顺带记：HMAC-SHA256、SHA-3、BLAKE2 都不吃这招，别拿它们空转。

## [g-flow] 实战解题流程——从拿到一串神秘字符到拿到 flag 的路线图

### [flow-decision] 解题决策树 | easy | 解题流程;决策树 | 解题思路
> 面对未知密文按固定分支走：编码 → 古典 → XOR → RSA → 综合，避免乱试。

#### 这个条目的作用

拿到一串神秘字符，最常见的死法不是解不开，而是**方向错了乱试一通**：把 Base64 当 RSA、把哈希当加密、把隐写当密码。本条目给一张「拿到密文先干什么」的完整决策流程，按长度→字符集→形态分级下判断，把题目快速归类到「编码 / 古典 / 现代 / RSA / 哈希 / 隐写」六个抽屉，每个抽屉配一条已确认的打法。五分钟内定方向，比盲试两小时强。

#### 前置条件

- 原始密文的一个备份（没备份就先复制一份到记事本）。
- CyberChef（网页版 https://gchq.github.io/CyberChef/ 即可）。
- 会用 `wc -c` / `len()` 数长度，能肉眼分辨 `A-Za-z0-9+/=` 这类字符集。

#### 第 1 步：备份 + 三查（30 秒固定动作）

解任何东西前先做三件小事：

1. **备份原始密文**：工具会自动改大小写/去空格，改坏了没处还原。
2. **数长度**：`echo -n "密文" | wc -c`（或看编辑器右下角）；记下是不是 4/8 的倍数、是否偶数。
3. **看字符集**：扫一眼都用了哪些字符（只有 `0-9a-f`？有大写 `A-Z2-7`？有 `=/+%`？有 `. -`？）。

**预期结果**：一张纸写下「长度=？，字符集=？，特殊符号=？」。**如果不行**：密文太长就先取前 200 字符看特征。

#### 第 2 步：过决策树，把题目装进一个抽屉

```txt
拿到题目/密文
│
├─ 密文是纯符号/短串（点划、两字符、图形）→ 编码类：
│    点划空格 → 摩斯；两字符 → 培根/二进制；六符号长串 → JSFuck；图形符号 → 猪圈
│
├─ 密文只有字母（无数字符号）→ 古典密码：
│    数长度+找重复片段 → 维吉尼亚（Kasiski/IC）→ 凯撒（25 位移）
│    字母频次正常但顺序怪 → 换位类（栅栏）
│
├─ 密文是 hex 串，长度与明文相近 → 现代密码：
│    与单字符异或后可读 → 单字节 XOR
│    提供加密接口/可提交解密 → ECB/CBC 攻击、Padding Oracle
│
├─ 题目给了 n/e/c 或 pem 公钥 → RSA：
│    factordb 查 n → 分解出 p,q 直接解
│    e 很小 → iroot 开方；多个 e 同一 n → 共模；多个 n → 两两 gcd
│    e 巨大 → Wiener（低 d）
│
├─ 给了哈希值 → 撞库 / 0e 弱比较 / 长度扩展（看题目场景）
│
└─ 以上都不像 → 隐写（图片/文本隐藏信息）、emoji 隐写、多层编码嵌套
```

**预期结果**：能指着树说出「这条应该是 XX 分支」。**如果不行**：先跑 CyberChef `Magic`（自动识别），让工具替你分类。

#### 第 3 步：编码分支实战（符号、短串、`=/+/%`）

按特征对号入座，全部交给 CyberChef：

- 点划空格 → `Morse Code Decode`（注意 `_` 与 `-` 的写法差异）。
- 两字符循环（`0101`、`AABB`、大小写混排）→ 培根密码或二进制，按 5 位/8 位分组。
- 超长 + 只有 `[ ] ( ) ! +` → JSFuck，浏览器 console eval 或在线解码。
- 图形符号（井字格带点）→ 猪圈密码查表。
- `%xx` → `URL Decode`；`\uXXXX` → `Unicode Text Format`；`&...;` → `From HTML Entity`。
- Base64 家族 → `From Base64`；含 0/O/I/l 缺失特征 → `From Base58`；大写 `A-Z2-7` → `From Base32`。

**预期结果**：解出可读内容（或再一层密文）。**如果不行**：解出来的还是乱码 → 很可能套了多层，回到第 1 步重新看新串的特征。

#### 第 4 步：古典密码分支实战（纯字母）

- 数长度 + 找重复片段：重复片段的间隔能整除出密钥长度 → **维吉尼亚**，直接用 dCode Vigenere 或 guballa.de 自动破解。
- 只有 25 种位移、字母整体平移 → **凯撒**，25 种全试，看哪个可读。
- 字母齐全但顺序奇怪、频次正常 → **栅栏**（W 形），栏数 2..10 试。
- 单表替换但无平移规律（频次分布保留）→ **仿射**（a 12 种 × b 26 种穷举）。

**预期结果**：看到可读英文/flag。**如果不行**：确认密文是否被统一转了大小写（大小写信息丢失会害死凯撒/培根）。

#### 第 5 步：现代密码与 XOR 分支实战（hex / 可提交解密）

- 纯 hex 且长度接近明文 → 单字节 XOR：256 个 key 全试，用英文字母频次评分选最高分。
- 长度很长、像循环异或 → 多字节密钥 XOR：先用汉明距离法求密钥长度再分组破（或 `xortool` 一键）。
- 题目**提供加密/解密接口**、返回可控制 → 按返回特征走：相同明文块密文相同 → ECB 重排/逐字节爆破；能收到填充错误差异 → Padding Oracle；Cookie 可控 → CBC 字节翻转。

**预期结果**：拿到明文或构造出合法密文。**如果不行**：先 `bytes.fromhex()` 再异或，字符串直接按字节异或是最常见的翻车点。

#### 第 6 步：RSA 分支实战（给了 n/e/c 或 pem）

固定顺序，白捡分动作放最前：

1. `openssl rsa -pubin -in pub.pem -text -noout` 提取 n、e（给 pem 时）。
2. **把 n 丢进 factordb.com 查一下**——小素数乘积、已知因数直接秒解。
3. e 很小（3/17）且明文短 → `gmpy2.iroot(c, e)` 开方。
4. 同一 n 两个 e、同一明文 → 共模攻击（`gcdext` 求 s,t）。
5. 多组 n → 两两 `gcd` 找共享素数。
6. e 特别大 → Wiener 连分数（低 d）。

**预期结果**：long_to_bytes 出明文。**如果不行**：核对进制——openssl 给的是 hex，题目若给十进制别混用。

#### 第 7 步：哈希分支实战（32/40/64 hex）

- 先对表说算法名（MD5=32、SHA1=40、SHA256=64）。
- 弱口令 → cmd5.com/somd5.com 撞库；hashcat 字典+规则爆破。
- PHP 场景 + `==` → 0e 弱比较。
- 校验是 `hash(secret + data)` + MD/SHA 系 → 长度扩展。

**预期结果**：拿到口令明文或绕过校验。**如果不行**：加盐了？试 `盐+口令` 拼接，或回读生成代码。

#### 第 8 步：兜底与结束条件

六个抽屉都翻完还没戏 → 最后一个抽屉：

- 图片附件 → 隐写：`binwalk`、`zsteg`、LSB 提取、文件尾追加数据。
- 纯文本藏东西 → 零宽字符、emoji 频率、大小写隐写、行首字符拼接。
- 以上全部失败 → 回读题目描述：难度标签、提示词、文件名、压缩包注释里往往有算法名或密钥长度。

**结束条件**：拿到 flag 格式串（`flag{...}`/`ctf{...}`）就算通关；一小时没进展就换题，别和一道题死磕。

#### 常见错误与排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 乱试工具 | 没分类 | 坚持先过决策树第 1-2 步 |
| 解出乱码以为是失败 | 只解了一层 | 解一层看可读性，不可读就按新串特征继续 |
| 把编码当加密 | 方向性错误 | 先问「这串的字符集暗示什么」，别先想 RSA |
| 大小写/空格被工具改掉 | 粘贴工具自动处理 | 用第 1 步的备份重来，工具尽量用 Python 复现 |
| n/e/c 进制混用 | hex 与十进制混算 | 统一格式，Python 里 `int(x, 16)` / `int(x)` 分清 |

#### 实战要点

- 决策树的核心是「数长度 → 看字符集 → 看特殊形态」三步，练成肌肉记忆。
- `factordb` 与 CyberChef `Magic` 是两道白捡分动作，每题先跑不亏。
- 现代 CTF 常见组合拳：hex → Base64 → 摩斯 → flag，解完一层永远检查可读性。
- 分类失败大概率是信息不足：先读完题目描述再动手，提示词通常在描述里而不在密文里。

### [flow-pitfall] 常见坑与踩坑点 | easy | 常见坑;易错点 | 踩坑指南
> 解码/解密结果不对时，先检查这些高频错误，往往比换工具更有效。

#### 这个条目的作用

解不出结果时，90% 的情况不是密码学知识不够，而是**输入数据被搞坏了**：大小写被转换、空白没清理、进制混用、字节和字符串分不清、只解了一层就当完事。本条目把 CTF 里反复出现的翻车点集中成一张自查表，按「数据卫生 → 逐行对表 → 多层嵌套 → 重读题目 → 换工具复现」五步走，多数卡壳能在十分钟内定位。

#### 前置条件

- 一份「解不出」的密文或一组算不对的参数。
- 第 1 步做的原始备份（没有就先备份）。

#### 第 1 步：数据卫生检查（每次必做）

按顺序过三件事，改数据类坑基本清零：

1. **保留原大小写**：密文先复制一份原始版。绝大多数工具（尤其网页版）默认转小写，而 Base58、凯撒、培根的大小写区分是有意义的。
2. **清理空白**：把换行/首尾空格先去掉（但**先确认空格不是分隔符**——摩斯、培根、栅栏可能故意用空格分组）。
3. **确认载体字节**：hex 串先转字节再异或；Base64 里混进了 `%0A` 这种 URL 编码先解码。

**预期结果**：一份「干净、原样、可复现」的输入。**如果不行**：连原始备份都没有就从题目附件重新取。

#### 第 2 步：逐行对高频坑自查表

解不对、算不对、绕不过时，一行行过这张表：

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| Base58 大小写敏感 | 结果乱码 | 确认题目字符串保留大小写再解（Base58 中 A ≠ a） |
| 密文被统一转小写 | 凯撒/维吉尼亚解不出 | 先保留原大小写；培根的大小写混排本身就是信息 |
| 空格/换行干扰 | 解码失败或多余字符 | 区分「噪音空白」（删掉）与「分隔空白」（保留） |
| 末尾换行没去掉 | 哈希对不上、长度算错 | 哈希/加密前 strip 尾部 `\n`/`\r\n` |
| 长度不是块倍数 | 分组/填充计算全错 | AES 前先 PKCS7 补齐；XOR 前确认已经 `bytes.fromhex()` |
| hex 与文本混淆 | 直接把字符串当字节异或 | 先 `bytes.fromhex()` 得到字节再操作 |
| n 进制搞混 | RSA 全错 | openssl 给 hex、题目可能给十进制；Python 里 `int(x,16)` 标清 |
| 多层编码只解一层 | 结果还是乱码以为失败 | 解完一层看可读性，不可读按特征继续解下一层 |
| emoji/零宽字符 | 明文藏在显示层之下 | 统计 emoji 频率转数字；用 `xxd` 看零宽字符 |
| 工具自动改数据 | 手算对、工具错 | 换 Python/CyberChef 复现，别纠结「我明明对了」 |
| 全角字符/中文标点 | 解码器不识别 | 确认密文是半角 ASCII，全角先统一转半角 |

> [!warn] 把密文粘进工具前先备份原始副本，很多工具（尤其网页版）会自动做大小写/空格处理。改坏的数据会让所有后续排查白费，这是最贵的隐形坑。

**预期结果**：至少一条「现象」命中，按对策修正后继续。**如果不行**：全没命中 → 数据没问题，问题在算法选择，回决策树重分类。

#### 第 3 步：检查「多层嵌套」假设

「解出来还是乱码」不等于失败——先判断这层结果**可不可读**：

- 可读（英文/数字/flag 字符）→ 结束，收 flag。
- 看起来像编码（全是 `=`、`%xx`、点划、两字符）→ 按新串特征再解一层。
- 常见链条：`hex → base64 → 摩斯 → flag`、`base64 → 栅栏 → 凯撒`、`两字符 → 培根 → flag`。

```bash
# 拿新串重新过一遍特征
echo "解出的新串" | wc -c
# 看字符集：只含 0-9a-f？含 =/+/%？只有 . - ？
```

**预期结果**：识别出「第二层」的编码类型。**如果不行**：新串看不出任何特征 → 丢给 CyberChef `Magic` 自动识别。

#### 第 4 步：重读题目，找漏掉的提示

数据与算法都没问题时，信息缺口通常在题目本身：

- 描述/附件名/压缩包注释里常直接给算法名、密钥长度、盐值拼接顺序。
- 标题或标签会剧透（如题目叫 small_e、common_modulus）。
- 难度标签有用：easy 题基本是单层编码或白捡 RSA，hard 才考虑多层/数学攻击。

**预期结果**：找到一句「哦原来提示在标题里」。**如果不行**：题目描述真的没信息，进下一步换工具复现。

#### 第 5 步：换工具/换语言复现（排除工具幻觉）

同一条密文用第二个独立实现验证（CyberChef 与 Python 各算一次）：

```python
# 例：核对一次 base64 解码
import base64
print(base64.b64decode("密文串").decode("utf-8", errors="replace"))
```

**预期结果**：两种实现结果一致，确认数据本身。**如果不行**：两种实现结果不同 → 原始数据被粘贴时改坏了，回第 1 步取备份重来。

#### 常见错误与排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 手算对、在线工具错 | 工具自动改数据 | 用 Python 复现，别信网页工具的预处理 |
| 换了好几个工具都一样乱 | 只解了一层 | 走第 3 步看可读性，继续解下一层 |
| 哈希对不上 | 尾随换行/大小写 | strip 空白、统一小写后再哈希比较 |
| 卡在「以为解完」 | 把中间产物当结果 | 中间产物常是下一层密文，特征重新识别 |
| 浪费一小时后发现提示在标题 | 没重读题目 | 卡 15 分钟就重读描述/文件名/标签 |

#### 实战要点

- 五个踩坑点按频率排序：大小写被改、空白没清、没 bytes 化、只解一层、进制混用。
- 「工具改了数据」是复现不了时第一个怀疑对象，永远保留原始备份。
- 明文解出来带 `\n` 或空格尾随很常见，先 strip 再比对或提交。
- 卡壳读题优先于换工具：CTF 提示十有八九在描述、标题、文件名里，不在密文里。
