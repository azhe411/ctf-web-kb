# 举一反三：换题怎么打

> 本篇把"这一道题"的方法，总结成"这一**类**题"的打法。
> 核心一句话：**骨架是通用的，payload 按题换。** 看懂这篇，你就能把同一套思路搬到别的题目上。

---

## 1. 先看骨架：什么才是通用的

`solver.py` 其实是两层东西：

```
┌─────────────────────────────┐
│  第一层：骨架（所有时间盲注通用）│
│  发请求 → 读耗时 → 二选一 → 枚举 │
│  换的只是"探测器怎么构造"        │
├─────────────────────────────┤
│  第二层：payload（这类题专用）    │
│  ^(?=猜的前缀)([\s\S]+)+(?!)   │
│  换题时按场景换零件              │
└─────────────────────────────┘
```

**骨架**换个 payload 就能打：SQL 时间盲注（`sleep(1) IF ...`）、布尔盲注（真/假页面不同）、报错盲注……全都是"发请求 → 观察 → 二选一 → 枚举"。

**payload** 只对"用户可控正则 + 秘密是匹配目标 + 回溯型引擎"这类题有效。

## 2. 拿到新题，30 秒自检（是否是"亲兄弟"）

依次回答，**全部为"是"**才直接套脚本：

| # | 问题 | 怎么查 |
|---|---|---|
| 1 | 源码里有用正则匹配，且目标/模式里藏着 flag？ | 读源码，找 `preg_match` / `re.search` / 正则字符串 |
| 2 | 正则内容我能控制？ | 找用户输入直接拼进正则的地方（如 `'/'.$x.'/'`） |
| 3 | 有耗时回显？ | 找 `echo microtime`、`exec_time`、`response time` |
| 4 | 引擎是回溯型？ | PHP(PCRE) / Python(re) / Node(V8) / Java 都是；**Go RE2、Rust regex 不是** |

任何一个"否"，跳到第 4 节看怎么改。

## 3. payload 三件套：换零件的完整手册

任何 ReDoS 探测 payload = 三个零件：

| 零件 | 作用 | 常见变体 | 什么时候换 |
|---|---|---|---|
| ① 前置检查 | 猜对了才进炸弹 | `^(?=K)` 前缀 · `(?=.*K$)` 后缀 · `(?=[\s\S]{n}$)` 长度 · `(?=.*K)` 包含 | 想测的位置不同 |
| ② 炸弹 BOMB | 制造回溯歧义 | `([\s\S]+)+` · `((.+)+)+` 更狠 · `(.+)+(.+)+` 双叠 · `(\w+)+` | 信号弱/噪声大时加厚 |
| ③ 失败点 FAIL | 必然失败且无字面量 | `(?!)` · `(*FAIL)`(PCRE2) · `(a+)+z`（z 必须存在于 flag！慎用） | `?` 被过滤时 |

**实测过的变体对比（新服务器）**：

| 变体 | 命中 | 未命中 | 比值 | 结论 |
|---|---|---|---|---|
| 原版 `(?!)` | 2.75ms | 58µs | 47x | ✅ 可用 |
| 叠层 `((.+)+)+` | 3.82ms | 55µs | 69x | ✅ 更强 |
| 双炸弹 `(.+)+(.+)+` | 3.16ms | 66µs | 48x | ✅ 可用 |
| 换失败点 `(*FAIL)` | 3.23ms | 53µs | 61x | ✅ 可用（注意偶发抖动） |
| 受限 `(a+)+z` | 55µs | 61µs | 1x | ❌ **无信号**：z 不在 flag → 预检短路 |

**核心规则（背下来）**：炸弹要能匹配任意字符（`[\s\S]`）；失败点不能是具体字符（会被必需字符预检短路）；`(?!)` 是同时满足两者的最优解。

### 换完必做的校准（3 分钟）

1. 拿一个**肯定对的**猜测 + 一个**肯定错的**猜测；
2. 各测 3 次取中位数；
3. **比值 ≥ 10 才继续**，否则换零件重来。

工具就是 `payload_test.py`，改 `probes` 列表即可。

## 4. 变种情况怎么改

### 4.1 引擎不同

| 引擎 | 能不能用 ReDoS | 注意 |
|---|---|---|
| PHP PCRE（本题） | ✅ | 有回溯上限(默认100万步)，命中稳定毫秒级，最友好 |
| Python `re` | ✅ | `(?!)` 合法；但没有回溯上限，命中可能拖到秒级，把 tries 调成 1 + 超时短一点 |
| Node V8 | ⚠️ | 能回溯但有保护机制，信号较弱，试试才知道 |
| Go RE2 / Rust regex / RE2 系 | ❌ | 线性时间，根本不回溯。**换思路**：找 bool oracle（匹配否回显不同）、报错差异等 |

判断引擎最快的方法：看题目页面/源码提示（PHP 就有 `preg_match`，Python 题一般给 Flask/Django 特征）。不确定就先发个炸弹试试，全快就是线性引擎。

### 4.2 回显渠道不同

| 回显什么 | 怎么办 |
|---|---|
| 服务器回显耗时（本题） | 直接用，最稳 |
| 只能自己测 RTT（掐表） | 噪声大：测 5-10 次取中位数；加厚炸弹（`((.+)+)+`）；阈值放宽 |
| 回显"匹配成功/失败"（bool） | 不用时间了：探测正则直接写 `^(?=猜的).*`，看返回 true/false 就行（更简单，但要求能看匹配结果） |
| 回显匹配到的内容 | 更简单：`(?<=前缀)(.)` 之类直接抓，不需要时序 |

### 4.3 输入被过滤（WAF）

| 被拦什么 | 绕过思路 |
|---|---|
| 拦 `?`（lookahead 死） | 失败点换 `(*FAIL)`；若 `*` 也被拦，用 `(a+)+z` 但要选 flag 里存在的 z |
| 拦 `(`（分组死） | ReDoS 基本无解，换查找其他漏洞（SSTI、注入等） |
| 拦 `^`（锚点死） | 用 `\A`；或去掉锚点改用"包含"探测 `(?=.*K)` |
| 拦 `[\s\S]` | 换 `(.+)+`（flag 无换行时等价）、`(\w+)+` |
| 拦 `$` | 后缀探测改用 `\z`（如果支持）；或干脆只打前缀，全从前端提取 |

### 4.4 flag 格式/字符集奇怪

- 含中文 → `CHARSET` 加中文字符，`requests` 会正确编码；
- 含 `/` → PHP 里会破坏定界符，探测时发 `\/`（转义）；
- 含空格 → 用 `%20` 测试，或直接加进 `CHARSET`；
- 长度大于 100 → `solver.py` 的长度循环是 1..100，改大一点。

## 5. 骨架的泛化：不止 ReDoS

时间盲注家族都长一个样：**"猜对了 → 可观测的差异"**。把"差异"换成别的就行：

| 差异类型 | 典型 payload 举例 | 适用场景 |
|---|---|---|
| 时间（本题） | 正则炸弹 / SQL `IF(条件, SLEEP(1), 0)` | 页面不区分对错时 |
| 布尔（页面内容不同） | SQL `IF(条件, 1, 0)` 拼进查询，看返回行数 | 页面区分对错时 |
| 报错（错误信息不同） | SQL `AND (SELECT 1/0 IF...)`、XPATH 报错注入 | 开启错误回显时 |
| 响应长度不同 | 拼接字符串长度随条件变化 | 内容部分可控时 |

**枚举逻辑完全一样**：先探长度 → 逐字符二选一 → 验证。`solver.py` 的骨架（并发扫描、中位数、确认、前后夹击）能直接复用，只改"探测器怎么发"这一层。

## 6. 实战决策树（贴墙版）

```
拿到 Web 题
└─ 能控制正则/查询，且秘密是匹配目标？
   ├─ 是 → 有耗时回显？
   │        ├─ 是 → ReDoS 时间侧信道（本知识库套路，直接跑 solver）
   │        └─ 否 → 有匹配结果回显？→ 是 → bool/内容 oracle（改探测器）
   └─ 否 → 按漏洞类型走别的技能树（注入/上传/反序列化...）
```

## 7. 练习建议

1. **先把本题跑熟**：对着 README 手动发 3 个请求（5、7 节），再跑一遍 `solver.py`，直到你能独立解释每一行输出。
2. **玩 payload 变体**：把 `payload_test.py` 里的炸弹换成 `((.+)+)+`、失败点换成 `(*FAIL)`，观察信号变化——换一次你就理解三件套了。
3. **找同类历史题**：上 CTFtime 搜标签 `ReDoS`、`regex`、`side-channel`，先看 writeup 确认题型，再自己写脚本复现。
4. **进阶**：把骨架移植去解一道 SQL 时间盲注题（先手写 `IF(SLEEP)`，再想办法自动化）。

## 8. 一句话总结

> 这类题只有两个难点：**想到"正则耗时"能当信号用**（侧信道直觉），和 **`(?!)` 这个绕过 PCRE 预检的构造**（ReDoS 知识）。剩下的全是"发请求→读数→枚举"的体力活，交给 solver.py 的骨架。
> 换题时：先自检 4 问 → 套骨架 → 换零件 → 校准（比值≥10）→ 上全量 → 三方验证。
